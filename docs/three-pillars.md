# Os três pilares

## 1. Arquitetura clara

Antes da implementação, registre objetivo, fronteiras, dependências, responsabilidades e critérios de aceitação. Um agente deve saber o que pode decidir e o que precisa devolver para revisão humana.

## 2. Desenvolvimento simultâneo coordenado

Divida o trabalho em unidades com baixa sobreposição. Cada unidade deve ter entrada, saída, arquivos sob responsabilidade e dependências conhecidas. A coordenação deve resolver conflitos de contrato antes que eles apareçam como retrabalho.

## 3. Validação por evidências

Separe intenção de comprovação. Uma afirmação de conclusão deve apontar para teste, inspeção, demonstração ou evidência equivalente. Quando algo não foi verificado, marque como `NOT_VERIFIED`.

## Regra de evolução

Um projeto só avança de fase quando os três pilares estão suficientemente atendidos para o risco daquela fase. A regra não exige perfeição; exige clareza sobre o que está pronto, o que está pendente e quem precisa decidir.
